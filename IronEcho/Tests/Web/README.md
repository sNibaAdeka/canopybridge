# Release QA браузерной игры (`qa.js`)

Одна команда проверяет ту же сборку, что работает на сайте (`/play`) и внутри `IronEcho.exe`:

```
python Tools/Build/Web/build_web.py site                                   # Build/Web/standalone
python Tools/Build/Web/check/synthetic_session.py Build/Web/check/synthetic_session.json
IRONECHO_SYNTHETIC=Build/Web/check/synthetic_session.json node Tests/Web/qa.js   # нужен playwright (NODE_PATH)
```

`--only=flows,ui,ring,camera,offline,soak` — выборочно. Код выхода 0, только если все проверки зелёные.

| Блок | Что проверяет |
|---|---|
| flows | полный бой до экрана результатов на каждом уровне и в коротком режиме; реванш; пауза по Esc останавливает правила; продолжение через проверку готовности и отсчёт; груша принимает удары |
| ui | меню влезает в 1280×720; иконка; «Лёгкий» по умолчанию; Enter — в ринг и реванш; Esc на результатах — меню; пауза при потере фокуса; смена графики на лету; нет горизонтальной прокрутки на телефоне |
| ring | клавиши W/S/A/D, Q/E, Shift+J/K доходят до ядра; робот шагает назад, а бот следует; круг поворачивает линию боя; роботы стоят там, где их ставит ядро, и лицом друг к другу; ноги делают шаги |
| camera | синтетический человек (MediaPipe-координаты, 60 к/с) проходит калибровку по подсказкам на экране, бой начинается, удары телом доходят до соперника, наклон к экрану шагает роботом вперёд |
| offline | игра и модель камеры грузятся при заблокированных внешних запросах; шрифты локальные |
| soak | три боя подряд не копят объекты сцены, геометрии и текстуры |

Телефон как камера (через настоящий лаунчер): `node Tests/Web/phone_e2e.js` — нужен `Build/Desktop/ironecho-linux`
(`build_desktop.py`); с `IRONECHO_FAKE_VIDEO=<y4m с человеком>` проверяет и распознавание позы.

Рендер идёт через SwiftShader (без видеокарты): медленно, но одинаково на любой машине. Бой прокручивается
крюком `IRONECHO_APP.debugAdvance` фиксированными шагами 1/60 с — те же правила и анимация, что в живой игре.
Чего этот набор не заменяет: живого человека перед камерой (освещение, одежда, расстояние) и FPS на настоящей
видеокарте.

Онлайн-дуэль (две настоящие страницы Chromium + локальный посредник PeerJS, интернет не нужен):
`NODE_PATH=<node_modules с playwright и peer> node Tests/Web/online_e2e.js` — код комнаты и ссылка, неверный код, вход по ссылке,
оба доходят до боя, действия каждого видны у обоих, позиции и здоровье совпадают, хэши состояния совпадают, пауза/продолжение/реванш,
уход соперника. (`npm i peerjs@1.5.4 peer@1.0.2`.)

Откат в сети (без браузера, быстро): `node Tests/Web/rollback_net.mjs` — два настоящих ядра WebAssembly (нужен `Build/Web/core/ironecho_core.wasm`) играют через
смоделированную сеть (задержка, разброс, несимметричные каналы, поздний старт, медленные кадры) и обязаны прийти в то же состояние, что эталонный прогон без сети;
печатает, за сколько кадров стартует собственный удар (откат против прежнего lockstep).

Рейтинг: `node Tests/Web/rating_test.mjs` (Эло, ники, запись боя → повтор на свежем ядре бит в бит, подделки, повтор записи, очередь без сети, забытый бой;
клиент `RatingClient` против настоящего серверного кода с хранилищем в памяти) и страница: `IRONECHO_STANDALONE=Build/Web/standalone NODE_PATH=<playwright> node Tests/Web/rating_e2e.js`
(ник, занятый ник, рейтинговый бой, таблица, выход из боя = поражение, закрытая вкладка = поражение при следующем запуске; запросы страницы к `/api/ratings`
перехватываются и обслуживаются тем же серверным кодом). База и сеть в этих тестах не участвуют.

Непрерывность анимации (`node Tests/Web/qa.js --only=animation`): 30-секундный бой со скриптом (удары, блоки, шаги, пинки, пропущенные удары),
каждый шаг 1/60 с замеряется по костям обоих роботов: корень не телепортируется (<0,10 м за кадр), конечности не переворачиваются на 180° за кадр,
локоть/колено/стопа не прыгают на полметра. На версии до исправлений тест красный (0,28 м, 180°, 0,79 м).

Вторая камера (страница игры + «телефоны» на настоящем WebRTC, локальный посредник):
`NODE_PATH=<node_modules с playwright и peer> node Tests/Web/camera2_e2e.js` — меню «Вторая камера», ссылка/QR с кодом комнаты и слотом,
страница телефона выходит «в эфир», игра декодирует видео и гонит позу по обоим потокам в слияние, уход и возврат телефона, режим
«2 телефона». Камеры — тестовый узор Chromium (человека нет, проверяются транспорт и проводка), математика слияния — отдельно:
`node Tools/Build/Web/check/check_fusion.mjs` (синтетическое тело с двумя видами: ошибка, поворот, сдвиг времени, потеря камеры, зеркало).
