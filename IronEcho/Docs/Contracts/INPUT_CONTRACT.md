## 1. Цепочка

```
камера ─► трекер (отдельный процесс, MediaPipe PoseLandmarker) ─► UDP 127.0.0.1 (LOCAL_PROTOCOL)
      ─► PacketGate (валидация, свежесть) ─► InputFrame ─► IntentMapper (гистерезис) ─► FighterIntent ─► правила (120 Гц)
клавиатура (отладка, F1) ──────────────────────► InputFrame ┘
```

Робот **постоянно повторяет стойку и уклоны** игрока (непрерывные поля). **Удары получают игровую обработку**:
трекер ловит начало удара, игра запускает собственный удар с замахом, активным окном и восстановлением.

## 2. Системы координат и единицы

| Система | Начало | Оси | Единицы |
|---|---|---|---|
| MediaPipe world (вход трекера) | середина таза | +x — **левая** сторона человека, +y — вниз, +z — от камеры | метры |
| **Тело (body frame)** | середина таза | **X — вперёд к камере/экрану, Y — анатомически вправо, Z — вверх** | метры / длины руки |
| Unreal | — | X вперёд, Y вправо, Z вверх (левосторонняя) | см |

Преобразование: `X = −z, Y = −x, Z = −y`. Оси body frame совпадают с осями Unreal, поэтому в компонентном
пространстве робота (смотрит в +X) вектор переносится без перестановки, только масштаб.

Проверено на реальном фото (MediaPipe 1.0.1, модель full): левое плечо `Y = −0.168`, правое `Y = +0.159`, голова над
тазом `Z = +0.608` (`python -m iron_echo_tracker probe-image <фото>`).

**Стороны всегда анатомические.** «Левый удар» — левой рукой игрока; робот бьёт своей левой. Экранное
отражение (селфи-превью) на данные не влияет.

**Зеркальная камера.** Если драйвер отражает картинку, MediaPipe путает стороны. Калибровка просит поднять ПРАВУЮ руку;
если MediaPipe назвал её левой — включается коррекция (обмен пар L/R + `Y → −Y`), флаг `bMirrorApplied`.

**Единица «длина руки» (AL)** = |плечо−локоть| + |локоть−запястье| по калибровке. Позиции кистей передаются в AL
от центра плеч — робот любого роста умножает их на свою длину руки.

## 3. InputFrame (v1)

| Поле | Тип | Диапазон | Смысл |
|---|---|---|---|
| `ContractVersion` | uint32 | 1 | версия этого контракта |
| `Status` | enum | см. §4 | пригодность ввода |
| `Confidence` | float | 0..1 | средняя видимость ключевых точек |
| `LeanLateral` | float | −1..1 (клип ±2) | уклон головы вбок; 1.0 = откалиброванный полный уклон; + = вправо |
| `LeanForward` | float | −1..1 | наклон к экрану; 1.0 = 25 см |
| `BlockAmount` | float | 0..1 | обе перчатки подняты выше стойки и у лица |
| `HandPos[2]` | Vec3 | ±3 AL | запястья относительно центра плеч, body frame ([0] левая, [1] правая) |
| `HandExtension[2]` | float | 0..2 | |запястье−плечо| / длина руки |
| `HandConfidence[2]` | float | 0..1 | min видимости плеча/локтя/запястья |
| `bMirrorApplied` | bool | | применена коррекция зеркала |
| `Punches[≤4]` | PunchIntent | | новые свежие удары с прошлого кадра |

`PunchIntent`: `PunchHand` (Left/Right), `Strength` 0..1 (в v1 только косметика: VFX/звук), `Confidence` 0..1,
`AgeSeconds` (от захвата кадра), `SourceEventId`.

Непрерывные поля сглажены фильтром One Euro (min_cutoff 2.5 Гц, β 0.3). Распознавание ударов идёт по несглаженным данным.

## 4. Статусы трекинга

| Status | Когда | Что делает игра |
|---|---|---|
| `Offline` | нет валидных пакетов > 0.35 с | пауза боя; HUD: «Трекер не отвечает» |
| `Starting` | трекер жив, камера/модель запускаются | ожидание |
| `NoCamera` | камера не открылась / не читается | HUD: проверить камеру; трекер переоткрывает раз в 2 с |
| `NoPerson` | человек не найден | пауза после 0.5 с; HUD: «Встаньте в кадр» |
| `LowConfidence` | видимость < 0.5 | как NoPerson; HUD: «Отойдите / больше света» |
| `NotCalibrated` | человек есть, калибровки нет | HUD: предложить калибровку |
| `Calibrating` | идёт калибровка | HUD: инструкция шага + прогресс |
| `Live` | всё в порядке | ввод идёт в бой |

Готовность к бою (`bInputReady`) = `Live`. Потеря на ≥ 0.5 с во время отсчёта/боя → `Paused(TrackingLost)`;
возврат после ≥ 1.0 с стабильного `Live` → отсчёт 3 с → продолжение (таймер раунда заморожен).

## 5. Действия v1

| Действие | Источник | Правило распознавания | Игровая обработка |
|---|---|---|---|
| Левый прямой (джеб) | событие трекера | рост вытяжения ≥ 2.0 AL/с **и** вперёд ≥ 1.4 AL/с, вытяжение ≥ стойка+0.10, прирост ≥ 0.16 за 0.25 с; перевзвод после возврата на половину или 0.6 с; не чаще 0.15 с на руку | старт атаки Left |
| Правый прямой (кросс) | то же | то же | старт атаки Right |
| Блок | `BlockAmount` | вход ≥ 0.60, выход < 0.45 | Block; удар игрока отменяет блок |
| Уклон влево / вправо | `LeanLateral` | вход \|lean\| ≥ 0.55, выход < 0.40 | Dodge; эффективен ≤ 0.9 с удержания, вход стоит 3 выносливости |
| Стойка | `HandPos`, `Lean*` | непрерывно | робот повторяет (HandTrackingAlpha = 1 в Guard/Block) |

Не в v1: хуки, апперкоты, удары в корпус, перемещение по рингу (дистанция держится автоматически), вторая камера, онлайн.

На синтетике (30/60 fps, 3 сида, зеркальная/обычная камера) распознаются все джебы/кроссы и связка 1-2, задержка
от начала движения до события **≤ 120 мс** (30 fps: ~100 мс; 60 fps: ~70 мс); ложных срабатываний на блоке,
уклонах, наклоне, опускании рук нет. **Пороги подлежат подтверждению на записях реального человека** (`run --record`).

## 6. Стадии атаки (правила, 120 Гц; 1 тик = 8.33 мс)

| Боец | Удар | Замах | Активное окно | Восстановление | Урон | Выносл. | Дальность | Стан при попадании |
|---|---|---|---|---|---|---|---|---|
| Игрок | левый | 0.09 с | 0.07 с | 0.20 с | 1.6 | 6 | 1.50 м | 0.22 с |
| Игрок | правый | 0.14 с | 0.07 с | 0.28 с | 2.8 | 10 | 1.45 м | 0.32 с |
| Бот Easy | л / п | 0.50 / 0.65 с | 0.07 с | как у игрока | 1.6 / 2.8 | 4.5 / 7.5 | | |
| Бот Normal | л / п | 0.40 / 0.55 с | 0.07 с | | | | | |
| Бот Hard | л / п | 0.34 / 0.48 с | 0.07 с | | | | | |

Здоровье 100 у обоих. Бот платит за телеграф: пока он в атаке, выносливость не восстанавливается, поэтому удары
бота дешевле (×0.75), а восстановление 18/с (у игрока 14/с).

Почему асимметрия: удар игрока уже прошёл ~0.1–0.15 с по камере, а человеку нужно ~0.25 с реакции плюс задержка
трекинга, чтобы физически уклониться — поэтому удары бота **телеграфируются** длинным замахом.

Прочие правила: буфер ввода 0.15 с; другая рука прерывает восстановление (связка 1-2); та же рука ждёт конца
восстановления; промах/уклон удлиняет восстановление на 0.10 с; встречный удар по замаху ×1.2. Дистанция: 1.35 м
между центрами, игрок подтягивается автоматически 0.9 м/с, отбрасывание 0.06/0.15 м, ринг ±2.60 м.

**Выносливость и защита (1.2).**
- Удар без достаточной выносливости — «удар рукой»: замах ×1.6, урон ×0.3, стан ×0.5, и он **не сбивает замах**
  соперника (урон проходит, удар соперника летит дальше).
- Выносливость опустела до 0 — **одышка 0.6 с**: новый удар не начинается (событие `StaminaExhausted`). Молотьба
  без остановки сама себя гасит; размеренный бой до нуля почти не доходит.
- Блок: 15 % урона (никогда не нокаутирует); блок платит 5 выносливости **за полный удар**, пропорционально его урону
  (вялый удар — ×0.3). Принятый в блок удар не сбрасывает задержку восстановления. Блок пробивается (GuardBroken),
  только если выносливости меньше цены этого удара. Стан блока 0.12 с.
- **Закрыться после пропущенного**: через 0.10 с стана можно поднять защиту (стан сменяется блоком), но бить
  нельзя до конца исходного стана. Серия «левой-правой» больше не держит соперника в оглушении бесконечно.

**Бот (1.2).** Реакция на замах игрока: Easy 0.09 с (джеб 0.09 с не успевает, только кросс), Normal 0.06 с, Hard
0.04 с; блок/уклон Normal 45/15 %, Hard 50/22 %, Easy 30/10 %. Читает серии: каждый удар после второго в пределах
0.6 с даёт +12 % к шансу блока (до 80 %). После удачного блока или уклона контратакует (Normal 35 %, Hard 55 %,
Easy 15 %). Атака, которую нельзя начать (оглушён, занят, далеко, нет сил), повторяется через 0.12 с, а не через
весь интервал. Normal/Hard чаще ждут, пока игрок закончит удар, и бьют в его восстановление. Против выдохшегося
игрока (выносливость < 15) давит: не закрывается от вялых ударов, интервал ×0.55. Раненый (< 30 % здоровья)
чаще закрывается (+15 % блок, +25 % защита в стойке) и реже бьёт (×1.25).

Проверка баланса: `Tests/CoreRules/TestBalance.cpp` и отчёт `Tests/Tools/Balance` (сотни боёв против модели
человека; цифры — `Docs/Reports/2026-10-04_balance/`).

Матч: 3 раунда × 90 с, перерыв 8 с (+15 % здоровья, полная выносливость). Тренировка: груша, без таймера.

**Нокдаун (1.1).** Здоровье 0 → нокдаун и счёт рефери 1…10 (раз в секунду, часы раунда стоят). Игрок встаёт, **подняв защиту
и удерживая её 1.2 с** (то же, что блок: `BlockAmount ≥ 0.6`), не раньше 2 с от падения. Бот встаёт по шансу уровня
(Easy 75/45/20 %, Normal 90/65/35 %, Hard 97/80/50 % за 1-й/2-й/3-й нокдаун) на счёт 3–8. После подъёма: здоровье 50 %
максимума (×0.7 за каждый следующий нокдаун в бою), выносливость 50 %, дистанция сбрасывается, пауза 1 с. Не встал к «10» —
KO. Третий нокдаун в одном раунде — TKO. Потеря трекинга во время счёта ставит паузу, счёт продолжается после возврата.

**Судьи (1.1).** Три судьи по системе 10-9: судья 1 — урон; судья 2 — урон + 3 × попадания; судья 3 — урон + 2.5 × (уклоны + блоки).
Разница ≤ 1 — 10-10; каждый нокдаун −1 очко (10-8), минимум 7. Итог: единогласное / раздельное / решение большинства,
ничьи тех же видов. Комбо: чистые попадания с интервалом ≤ 1 с подряд, пока сам не пропустил.

## 7. Порядок обновления в кадре Unreal

1. `AIronEchoGameMode::Tick` (TG_PrePhysics): `Poll()` сокета → `BuildInputFrame()` (или клавиатура).
2. `IntentMapper::Map` один раз за кадр; удары идут в первый под-шаг; если под-шага не было — переносятся.
3. `Match::Tick` × N фиксированных шагов 1/120 с (накопитель, кадр ≤ 0.25 с).
4. Визуальное состояние → бойцы/груша → события (`OnCombatEvent`, `OnMatchEvent`) → HUD-снимок.
5. Анимация (AnimBP Codex) читает `FIronEchoFighterVisualState` в своём `NativeUpdateAnimation`.

## 8. Калибровка

| Шаг | Инструкция (RU) | Instruction (EN) | Условие |
|---|---|---|---|
| Neutral | Встаньте в стойку и замрите | Stand in your guard and hold still | 1.5 с, std головы ≤ 3 см, кистей ≤ 5 см |
| RaiseRightHand | Поднимите ПРАВУЮ руку над головой | Raise your RIGHT hand above your head | одна кисть выше носа на 8 см, 0.3 с |
| SlipLeft | Уклон ВЛЕВО и задержитесь | Slip to your LEFT and hold | голова ≥ 8 см влево, 0.4 с |
| SlipRight | Уклон ВПРАВО и задержитесь | Slip to your RIGHT and hold | то же вправо |

Быстрая калибровка — только Neutral (зеркало и диапазоны уклонов берутся из прошлой). Тайм-аут шага 20 с →
`Timeout` или `LowVisibility`. Результат сохраняется у игрока: `%LOCALAPPDATA%\IronEcho\calibration.json`.
