# Сервер рейтинга IRON ECHO

Вызов: `/api/ratings` на публичном сайте (Vercel-функция, `ratings.mjs`). Логика не зависит от хостинга: `rating_api.mjs` (запрос → ответ), хранилище — `rating_store.mjs`
(`MemoryStore` для тестов, `SupabaseStore` для настоящей таблицы). Тесты: `Tests/Web/rating_test.mjs`, `Tests/Web/rating_e2e.js`.

## Как это устроено
- Страница пишет бой как последовательность вызовов правил (`site/src/replay.js`) и шлёт запись (gzip, ~30 КБ). Сервер проигрывает её на своей копии ядра
  (то же WebAssembly, что в странице; `release/api/core_build.mjs`) и сам определяет итог. Заявленный результат ничего не значит.
- Запись другой сборки ядра отклоняется (`old_version`): сервер принимает только ту сборку, что лежит в релизе. После любого пересборки ядра старые страницы и
  старый `IronEcho.exe` теряют возможность рейтинга до обновления.
- Эло: `site/src/ratingrules.js` (боты 900 / 1200 / 1500, старт 1000, K 40/32/24). Две таблицы: `keys` и `camera`.
- Ник: уникален по ключу (без регистра, пробелов, `_ . -`, кириллические двойники латинских букв считаются теми же буквами). Профиль = uuid + секрет (в базе только sha-256).
- Защита: повтор той же записи — `duplicate`; бои чаще раза в 15 с — `too_fast`; бой оставлен — поражение (`/api/ratings?op=forfeit`).
  **Предел защиты:** человек, который запустит ядро у себя и подберёт идеальный ввод, получит валидную запись. Таблица защищена от подделки запросом, не от программ-игроков.

## Включить на Vercel + Supabase (один раз)
Проект Supabase уже создан: `iron-echo`, ref `tboqtclodnlzqcllaaij`, `https://tboqtclodnlzqcllaaij.supabase.co`, схема применена (шаг 1 сделан).
1. Supabase: создай проект (бесплатного плана хватит), выполни `rating_schema.sql` (SQL Editor). Таблицы закрыты RLS: читает и пишет только ключ сервера.
2. В проекте Vercel `iron-echo-boxing` → Settings → Environment Variables: `SUPABASE_URL` (Project URL) и `SUPABASE_SERVICE_KEY` (secret / service_role key; **только на сервере**).
3. Передеплой. Без этих переменных функция отвечает `503 not_configured`, а страница показывает «Рейтинг сейчас недоступен».
4. Проверка: `GET https://<сайт>/api/ratings?ladder=keys` → `{"ok":true,"rows":[],...}`.

Модерация: удалить игрока — `delete from ie_players where nick = '...'` (рейтинги и бои уйдут каскадом).

## Анонимная статистика (1.7.0): `/api/events`
Страница (`site/src/telemetry.js`) пачками шлёт события: открыл страницу, нажал «В РИНГ», начал/закончил бой, первый удар, камера (попробовал / прошёл
настройку / не удалось), к/с раз в 30 с, ошибки. Без cookies, имён, адресов и видео: случайный id в localStorage. Выключается кнопкой «Статистика»
в меню, при Do Not Track и в автоматических браузерах (тестах). Сервер: `events.mjs` → `events_api.mjs` (только известные типы, ≤ 20 событий,
≤ 1 КБ свойств на событие, 60 запросов в минуту с адреса; адрес не хранится) → `events_store.mjs` → таблица `ie_events`.
**Включить:** выполнить `events_schema.sql` в SQL Editor проекта `iron-echo` (таблица ещё не создана — автоматическое применение было заблокировано);
переменные `SUPABASE_URL` / `SUPABASE_SERVICE_KEY` те же, что у рейтинга. Без них или без таблицы функция отвечает 503, игра не страдает.
Посмотреть: `select type, count(*) from ie_events where ts > now() - interval '1 day' group by 1 order by 2 desc;`
Тест: `node Tests/Web/telemetry_test.mjs`.
